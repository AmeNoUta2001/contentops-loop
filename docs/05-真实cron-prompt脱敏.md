# 真实 cron prompt（脱敏）

> 这份文档里的 prompt **不是示例，是从一个真实在跑的 agent 运营系统里抄出来的**，
> 每个 prompt 都标了它对应的脚本与调度（脚本名已按公开仓库的命名调整）。
>
> **脱敏口径**：账号身份、真实数据、以及这个账号调出来的**策略规则**（标题公式、骨架/池子清单等，
> 那是账号自己的资产）已隐去；凡是我删掉的地方都用 `【已隐去：…】` 明确标出，不做无声删改。
> **保留的是接线方式**：注入契约、输出契约、失败处理、护栏 —— 这些换任何账号都通用。

## 〇、五种接线方式

| 模式 | 干什么 | 关键机制 |
|---|---|---|
| A. 纯脚本看门狗 | 每 5 分钟查内存 / 每周清磁盘 | `no_agent`：不花 LLM，**健康时输出为空 = 不发消息** |
| B. 脚本注入 + agent 判断 | 每日数据复盘 | `script:` 先跑，stdout 注入 prompt，agent 只做判断 |
| C. 单一出口决策 | 每周方向合并 | 只允许写一个文件，**每周最多改 1 件事** |
| D. 可回复的周期卡 | 每周同题库周卡 | `attach_to_session`：用户回一句，agent 接着处理 |
| E. 证据蒸馏 | 每日把原始记录压成观察日志 | 只产证据、**禁止写方向**，防止下游读到断供的旧文件 |

---

## A. 纯脚本看门狗（`no_agent`）

最省钱的模式：**不调 LLM，脚本 stdout 就是消息内容；健康时不输出 = 用户不会被骚扰。**

````markdown
每 5 分钟检查物理内存可用量与 swap 使用率，仅当 MemAvailable<300MB 或 swap>60% 时
输出中文告警（交付飞书）；MemAvailable<200MB 时自动重启 hermes-chrome 释放浏览器栈。
健康时输出为空，不发消息。
````

````markdown
每周磁盘清理（无 LLM，纯脚本）：清理手机截图缓存、可再生包缓存、Chrome 调试缓存、
过期 cron 日志、分身日志、journal、过期养号归档、未引用历史配图，并输出一行磁盘摘要。
````

**可抄的点**
- 阈值写死在 prompt 里（人改 prompt 就改了行为，不用改脚本）
- **"健康时输出为空"** —— 这是 no_agent 看门狗的灵魂。否则每 5 分钟一条"一切正常"，没人看
- 分级动作：告警是一档，自动处置（重启浏览器栈）是另一档

## B. 脚本注入 + agent 判断（每日复盘）

这是主链路。`script: fetch_tt_stats.py` 先跑，stdout 被注入 prompt；agent 不取数，只做判断。

### B1 注入契约（prompt 里怎么描述"你手里有什么"）

````markdown
数据采集脚本 fetch_tt_stats.py 已自动运行，其 stdout 已注入到你的上下文中
（以 COOKIE_OK 或 COOKIE_EXPIRED 开头，含 SNAPSHOT 路径、全部已发布文章明细、PORTRAIT 画像行）。

**快照已含每篇展现量与 CTR（读/展），低阅读的文章也有，无需用户截图。**
````

> 注意三件事：① 告诉 agent **怎么判断注入是否成功**（看前缀）；② 告诉它**别重复取数**；
> ③ 告诉它**数据已经够全了**，不然它会去想办法补齐，浪费预算还可能编数。

### B2 角色与边界

````markdown
今日是执行日。你是头条创作后台数据复盘 agent。

**本任务角色：只做数据复盘与数据侧观察。**
禁止再建议【已隐去：一条已被用户作废的选题逻辑】类做法。
````

### B3 口径纪律（原样保留，这是最值钱的一段）

````markdown
**仪表盘只看首日三指标**：首日曝光 / 首日阅读 / 首日CTR。
⛔ 禁止用累计展现、累计 CTR 判断健康度或给建议 —— 平台从第 2 天起只给很小的量、CTR≈0 的
后续零星曝光，会把早期表现不错的内容在累计口径下稀释到接近 0。

**数据已机器化，直接用**：脚本已打印 `FIRSTDAY_OK …` 段并落盘 `首日指标.json` / `题材池子表.md`。
以该段为准：**不要自己手算、不要重跑取数脚本、不要改这两个文件。**

**诊断必须分成两件事**（两种死法不能混）：
  · 骨架旧（结构外壳与近期已发重复）→ 观察到**首日曝光极低、点击率却不低**；
  · 池子小（该题材受众本来就少）→ 首日曝光中等，**点击率正常也涨不上去**；
  · 第三因子：**账号当期分配额度**（同期所有题材一起掉量就是它）。
  模型：**首日曝光 = 骨架新鲜度 × 题材池子大小 × 账号当时分配额度**

**每期必出「题材池子表」**：题材 → 篇数 / 首日曝光中位 / 首日阅读中位 / 首日CTR中位，
按首日曝光中位降序 = **池子大小序**。
**必须用「剔爆款」列排序**：单篇爆款会把题材池子虚高中位数，禁止用爆款撑起的题材当池子证据。
备注列标「单篇」的题材样本不足，只作参考不得定级。

【已隐去：该账号的大池/小池题材清单 —— 那是标定结果，不是通用知识】
【已隐去：该账号的标题与骨架策略规则若干条】
````

### B4 输出契约（最该抄的一段）

**一次运行产出两件东西，短消息给手机、详报落盘。**

````markdown
**输出 = 两件东西：手机短消息 + 落盘详报（硬约束，违反即不合格）**

d1. **飞书消息（发给用户的这条，必须短）**：**全文 ≤ 24 行**，结构固定三段、顺序不许变：
    ① 第一行就是 `👉 今天要你做的事`：≤3 条，每条一行、≤30 字、祈使句；**没有事就写「无」**。
       这一段必须排在**最前面** —— 用户常在手机上只扫这一段，扫完就得知道要不要动手。
    ② `📊 关键数据`（≤12 行，**必须大白话，不许出现行业黑话**）：一行一个数，顺序固定：
       · 最近 3 篇阅读量（含与昨天的差值）；下面跟一行合计
       · 平台给量：最新一篇发布当天 N 人看到｜近 5 篇平均 N 人
       · 点开率：近 5 篇 x.x%｜过线线 N%
       · 达标进度：近 14 篇里有 N 篇过线
       · 最能起量的题材：XXX
       ⛔ **术语禁令（仅限短消息）**：不得出现「首日曝光中位 / 首日CTR / 池子 / 过线率 /
          骨架 / 内核」这类词；需要说就翻译成上面那几句大白话。**术语只在落盘详报里保留。**
       ⛔ 不要放表格、不要逐篇铺全部文章、不要解释原因（原因进详报）。
    ③ `⚠️ 判定点/风险`（≤2 行）：仅当触发决策门、撞到判定点日期、或有合规风险时才写，否则省略。
    末行固定：`📄 详情：<落盘路径>`

d2. **落盘详报**：除 d1 三段之外的全部内容一律写进 `复盘日报-<日期>.md`（写全写细），
    短消息里**不再重复**。

d3. 落盘文件必含：新发文章表现 / 最近 3 篇阅读量与日增长表（含"还在涨 vs 已停"判定）/
    在榜文章变化 / 账号权重观察 / 首日三指标与池子诊断 / 档位兑现复盘 /
    爆款信号与风险 / 读者画像摘要 / 单价与收益维度。
````

**可抄的点**
- **"短消息 ≤24 行 + 详报落盘"**：手机端只扫第一行，所以**第一行必须是"要你做的事"**
- **黑话禁令**：同一个系统里，短消息说人话、文件里说术语。这一条是用户提出来改的，效果立竿见影
- **"没有事就写「无」"**：否则 agent 会为了交作业硬凑三条建议
- 失败路径也写进 prompt：

````markdown
以 COOKIE_OK 或 COOKIE_EXPIRED 开头 —— 若 cookie 过期，**照实写「取数失败」并停止分析**，
不要用昨天的快照冒充今天，也不要从上下文里翻旧的数字来填表。
````

## C. 单一出口决策（每周方向合并）

抗污染的核心：**多个采集源只产证据，方向只有一个出口，且频次有上限。**

````markdown
你是本项目的**方向合并 agent（每周一次）**。

**你的唯一职责**：把多个采集源的证据合并成**一个**方向结论，
防止账号被这一周里冒出的多个热点带偏。

**第一步：read_file 以下文件（缺文件就跳过，不要报错停摆）**
1. `reports/decision_sources.md` —— 分层与「抗污染硬规则」，必须逐条遵守
2. `reports/骨架与池子-诊断框架.md` —— canon（只读）
3. 证据源：`reports/首日指标.json`、`reports/题材池子表.md`、`reports/topic_suggestions.md`、
   最近 2 份爆款研究、养号观察近 7 天条目
4. 上周的 `reports/方向决策-*.md`（取其「待议队列」段继续累积）

**第二步：写 `reports/方向决策-<YYYY-WW>.md`**（写前先 read；存在则保留其「待议队列」历史行
再覆盖其余段落），固定四段、顺序不许变：
1. `## 本周唯一变更` —— 一句话；**没有就写「本周不改变方向」**。有变更时必须附四要素：
   `证据（≥3 条，格式：来源｜事实｜数字）｜反证/风险｜生效日期｜撤销条件`
2. `## 继续执行（不要动）` —— 3 条
3. `## 禁止清单` —— 本周不许碰的骨架/题材/口径
4. `## 待议队列` —— 本周冒出来但**不采纳**的想法，每条一行，注明来源 + 不采纳理由
   （证据不足 <3 条 / 超出「每周一件事」额度 / 与 canon 冲突）

**第三步：给用户的飞书消息（≤8 行，手机友好，第一行就是结论）**
（格式模板略）

**⛔ 硬规则（违反即不合格）**
- **每周最多改一件事**，其余一律进「待议队列」
- **单篇爆款 / 单个账号的做法不得成为方向**：必须有 ≥3 条同向证据才算信号
- **不得改写 canon** —— 发现 canon 有问题只能在「待议队列」里提，不能自己动
- **本任务只允许写「方向决策-<周>.md」一个文件**，其他文件全部只读
- 证据不足时**明确写「本周不改变方向」**，不要为了交作业硬提建议；
  **宁可空着一周，也不要制造方向漂移**
````

**可抄的点**
- **"只允许写一个文件"** —— 这一条把"agent 到处改文件"的风险一次掐掉
- **"每周最多改一件事"** —— 频次上限比任何"请你谨慎判断"的叮嘱都有效
- **"宁可空着一周"** —— 明确给出"什么都不做"这个选项，否则 agent 默认要产出点什么
- **四要素**（证据/反证/生效日/撤销条件）—— 没有撤销条件的变更不是决策，是冲动

## D. 可回复的周期卡（`attach_to_session`）

发出去的卡片本身是可以回复的：用户回一句「3 错→护工视角」，agent 接着处理。

````markdown
你是本项目的同题库维护 agent（每周一次）。

**任务**：把本周的《同题库周卡》发给用户，并处理他对归类抽查的回信。

**步骤**
1. 前置脚本已经跑完，它已经刷新了统一库、重算了对照表、并生成好周卡正文
   （脚本 stdout = 周卡正文，已注入到本 prompt 上方）。
   **直接以那份正文为准**，不要重新统计、不要自己编数字。
2. **若用户在回报里对上一次周卡给了更正**，先做这两件事再发消息：
   - 在词典文件里按更正补关键词或新增母题（保持既有纪律）；
   - 重跑前置脚本，用新的正文发送。
3. **发送格式（手机优先，≤20 行）**：
   - 第一行必须是 `👉 要你做的事：…`
   - 然后 `📊 雪球：…`（累计体量 + 本周增量 + 离出结论最近的项）
   - 然后抽查清单，保留脚本里的分组
   - 末行 `📄 详情：<路径>`
   - ⛔ 不要贴表格、不要长篇解释；细节一律留在文件里。

**铁律（违反即不合格）**
- 分母只认「主页来源 / 自家」；推荐流、搜索来源的样本**不进分母**
- 只能同「文章年龄桶」比，只用桶内相对档；n<8 或跨账号<3 一律写「样本不足」，
  **不许硬给分布**
- ⛔ 禁止把分布写成「成功率/概率/命中率」，只能写「观察窗口内的表现分布」
- 数据不够就照实写缺；**不要**为了补齐样本去额外采集或搜索
````

**可抄的点**
- **"直接以脚本正文为准，不要重新统计"** —— 拦住 agent 二次加工（那是数字漂移的主要来源）
- **"禁止把分布写成成功率"** —— 同一个数字换个词就是过度承诺，这条要在 prompt 里堵
- **"不要为了补齐样本去额外采集"** —— 防止 agent 擅自扩大业务动作
- 抽查只挑"需要人判"的（像本赛道但没归类 / 低置信 / 否决词可能误杀），不丢垃圾给人审

## E. 证据蒸馏（每日，防断供）

采集通道换掉之后，下游读的日志文件**没人接手维护**了 —— 这类"静默断供"只有靠一个专职 cron 才能防住。

````markdown
你负责维护决策源「养号观察」日志：`reports/nurture/观察.md`

背景：原先由另一条采集会话 cron 每次追加观察；该通道下线后无人接手，日志已断供 N 天。
而写稿 cron 与周会 cron 都在读这个文件 —— **它们读到的必须是新鲜观察。**

素材：上一条消息已注入「观察·备料」摘要。若摘要显示无新会话/无素材，直接按要求收尾，**不要硬编**。

步骤：
1. 从备料里挑**信息量最大的 2-3 条**，读它们的全文。
2. 往 `观察.md` **末尾追加** 2-3 行：只追加，**禁止改写/删除任何已有行**。每行严格照既有格式：
   `- YYYY-MM-DD HH:MM 题材族：…｜标题骨架：…｜证据：…｜启示：…`
3. 启示必须是**技法层**（开头 3 秒怎么开／标题骨架怎么搭／落点怎么收／结构怎么排），
   要写清「我们能搬什么」。
4. ⛔ 只产证据与技法，**不得**写方向性结论 —— 方向只有周会一个出口。
   ⛔ 不得编造数字：只写备料里有的，没有就写「不可见」。
   ⛔ 单篇/单号不得升级为结论；同向观察要注明「连续第 N 次」。
   ⛔ 视频不参与（与图文互动不可比）。
5. 若备料显示本时段无素材 → 追加 1 行「素材异常」类观察（写明当天推荐流给的全是新闻），然后结束。

最后用 3-5 行汇报。若确实无素材可写，输出「本场无新素材，未追加」。
````

**可抄的点**
- **"只追加，禁止改写删除任何已有行"** —— 日志类文件的第一纪律
- **"不得编造数字：没有就写「不可见」"** —— 给 agent 一个诚实的出口，它就不会编
- **"素材异常"也是一条有效观察** —— 把"今天什么都没发生"变成结构化的事实，而不是省略

## 六、从这些 prompt 里能抄的东西（汇总）

1. **先声明手里有什么、怎么判断注入成功、不要重复取数**（B1）
2. **短消息 + 落盘详报双输出**；短消息第一行永远是「要你做的事」（B4）
3. **同一个系统里两套语言**：手机消息说大白话（禁术语），文件里保留术语（B4）
4. **给"什么都不做"一个明确写法**（「无」/「本周不改变方向」），否则 agent 会硬凑产出（B4、C）
5. **频次上限比语气叮嘱有效**（每周最多改一件事 / 重发每篇 ≤1 次）（C）
6. **限定可写文件范围**（"本任务只允许写一个文件，其余只读"）（C）
7. **每条变更必须带撤销条件**（C 的四要素）
8. **禁止二次加工**：脚本已经算好的数字，agent 只引用不重算（B3、D）
9. **数据不足时禁止下结论**，并要求写明「样本不足」（B3、D）
10. **日志只追加、不改写**；无素材时输出「无新素材」而不是编（E）
11. **失败路径写进 prompt**：取数失败就说失败，不许用旧数据冒充（B4 末）

> 这些不是理论 —— 每一条背后都对应一次真实的翻车。
> 翻车记录见 `docs/02-工程决策与踩坑.md`。
