# 换赛道 / 移植清单

> 前提问题：「如果有一天我不想写这个题材了，这套东西还能用吗？」
> 答案：**机器能，校准不能，账号更不能。** 下面是逐项拆解。

## 一、直接可用（垂类无关，一行不用改）

| 模块 | 为什么无关 |
|---|---|
| `fetch_tt_stats.py` · `fetch_income_overview.py` · `backfill_item_info.py` · `probe_tt_impression.py` | 纯平台取数，跟写什么没关系 |
| `first_day_metrics.py` 的**算法** | 首日窗口、去重、爆款剔除、汇总口径都是平台机制层面的 |
| `funnel_diagnosis.py` · `micro_diag_test.py` | 漏斗分层本身与题材无关 |
| `benchmark_store.py` 的**机器** | 分桶、分位、赛道 on/mixed/off 判定逻辑都是通用的 |
| `same_topic_*` 的**机器** | 入库、去重、分布、周卡结构通用 |
| `jev_replay_*.py` | 离线回放框架本身就是通用的 |
| `self_track.py` · `doctor.py` | 通用 |
| `secretctl.py` · `secrets_env.py` · `tt_cookie.py` | 凭据层 100% 通用 |
| `phone_ctl.py` | 设备层通用 |

## 二、必须重写（垂类相关，但只改**一个文件**）

全部集中在 `config/vertical.json`：

| 字段 | 换赛道要做的事 |
|---|---|
| `families` | 重写题材族 + 关键词（照你自己赛道的高频词） |
| `motifs` | 重写母题：这是最花时间的一项，要从你自己的稿件里归纳 |
| `motif_must` | 给容易误吃的母题加 AND 组 |
| `off_vertical` | 换掉跨垂类否决词 |
| `niche_pos` / `niche_neg` | 重写"同赛道判定"正反词（决定基准库里收哪些同行） |
| `niche_hint` / `offlike` | 重写抽样提示词 |
| `manual_overrides` | 清空重来 |

## 三、必须**重新标定**（最容易低估的一项）

`thresholds` 里的每个数字都是在原赛道的数据上标出来的，**换垂类照抄一定会错**：

| 阈值 | 为什么要重标 |
|---|---|
| `own_pass_ctr`（过线值） | 不同垂类的正常点击率区间不同 |
| `own_strong_ctr` | 同上 |
| `big_pool_show` / `small_pool_show` | 池子量级完全取决于垂类受众规模 |
| `viral_show` | "爆款"的定义随垂类变化 |
| `min_n_quantile` | 可以沿用（那是统计保守性，不是垂类属性） |

**怎么重标**：先采集 2–4 周，拿到你自己首日三指标的分布，再把分位数当阈值。不要拍脑袋。

## 四、真正的成本：没有基线

这是比改词表大得多的那部分，且**无法用代码解决**：

- 原赛道的判断（五档处置、停更门、池子大小序）全部依赖历史样本；
- 换赛道后前 2–4 周，你没有样本 → **五档处置不能执行**（它需要有参照）；
- 这段时间只能做两件事：① 采集，② 用绝对口径记录；
- 基准库（`benchmark_store.py`）也要在新赛道重新收集同行账号，而且**文章年龄桶的样本要攒够 8 篇**才开始有分位意义。

换句话说：**机制可以复用，历史数据不能。** 换赛道约等于重新起号。

## 五、最硬的一条：换赛道 ≠ 换账号

同一账号的兴趣池与分配额度是按历史内容训练的。在旧号上换题材，会被现有池子拖累 ——
平台大体上还是把你当原来的号看待，只是内容对不上读者，通常会得到"两边都不讨好"的结果。

所以真要转方向，现实做法是**开新号**：

| 走法 | 代价 |
|---|---|
| 同一账号硬转 | 现有读者流失，新题材拿不到匹配的池子，两头空 |
| 开新号（推荐） | 老号的收益/粉丝沉淀停摆，新号从 0 开始采集与校准 |

这套工具能帮上忙的是：**新号从第 1 天就把口径建对**（快照、首日三指标、题材池子从第一篇开始记），
不用像原号那样先摸索两个月才发现累计 CTR 会误导判断。

## 六、动手清单

```bash
# 1) 复制一份仓库当新项目（别在原目录上改）
cp -r content-ops-loop ~/new-vertical && cd ~/new-vertical

# 2) 换工作区根目录
export CONTENT_OPS_ROOT=~/new-vertical

# 3) 重写垂类配置
$EDITOR config/vertical.json

# 4) 自测：丢几条你新赛道的真实标题进去
python3 scripts/vertical.py
python3 scripts/topic_taxonomy.py "新赛道标题1" "新赛道标题2" "新赛道标题3"
#    只看两件事：归类对不对、有多少「未归类」

# 5) 接账号，开始采集（这周不做任何处置判断，只攒数据）
export TT_USER_ID=<新号 user_id>
python3 scripts/secretctl.py init && python3 scripts/secretctl.py set tt_mp_cookies --file cookie.txt
python3 scripts/fetch_tt_stats.py        # 每天跑

# 6) 攒够 14~30 天后再标定 thresholds，然后才启用五档处置
CONTENT_OPS_ROOT=~/new-vertical python3 scripts/first_day_metrics.py
```

## 七、一句话总结

| 层 | 能不能复用 |
|---|---|
| 取数 / 凭据 / 设备 / 回放框架 | ✅ 直接复用 |
| 诊断口径与处置逻辑 | ✅ 复用，但阈值要重标 |
| 题材词典 | ⚠️ 只改 `config/vertical.json` |
| 历史样本与基线 | ❌ 带不过去，必须重采 |
| 账号本身 | ❌ 建议开新号 |
